# 告别 access_token：把公众号草稿推送交给自建网关

写公众号的人大多经历过这样的流程：本地把文章排好版，复制 HTML，打开公众号后台，粘贴，调字体，传封面，再点保存草稿。文章一多，重复劳动就成了一种消耗。

更麻烦的是自动化方案。微信官方接口不打算让人轻松：`access_token` 两小时过期、调用必须来自白名单 IP、正文图片要先转存到微信自己的域名。任何一条不满足，推送就失败。

这篇短文介绍的项目 `wewrite-draft-gateway` 只做一件事：**把 WeWrite 的排版能力，接到一个已经解决掉上面所有麻烦的自建网关上。**

## 分工

- **WeWrite** 负责内容与排版：Markdown 进，微信兼容的内联样式 HTML 出，自带 18 套主题。
- **wx-draft-worker 网关** 负责与微信打交道：缓存 token、转存图片、生成封面、提交草稿，全部在 Cloudflare Worker 上完成。
- **本适配器（wewrite-draft-gateway）** 只负责把两者粘起来，并给你一条命令。

对接之后，你在本机只需要：

```bash
wewrite-push push article.md --cover cover.png --theme sspai
```

草稿就到了公众号草稿箱，剩下的只是打开后台点「发布」。你的电脑不需要固定 IP，你的配置里不需要 AppSecret。

## 为什么值得这样做

第一，**配置只有两项**。网关地址加一个 `wxk_` 开头的令牌，写在 `.env` 里，或者放进环境变量。公众号的 AppID 与 AppSecret 只存在于网关后台，不落在任何一台写作的电脑上。

第二，**换号只要一个参数**。如果你的矩阵里有多个公众号，用 `--account-id` 指定目标账号即可，不需要维护多份密钥。

第三，**失败看得懂**。微信返回的错误码（40164、40001、53500）会被翻译成中文提示，直接告诉你下一步该做什么，而不是让你去翻接口文档。

第四，**没有锁定**。适配器输出的就是标准 HTTP 请求，你也可以用 curl、用 Python、用任意语言调用同一个接口；甚至可以让 AI Agent 直接执行这条命令。

## 使用心法

把文章写作和草稿推送当成两个独立环节：写作时专注 Markdown，推送时只关心元信息——标题、摘要、作者、封面、目标账号。两者解耦之后，你可以在任何地方写，在任何地方推。

写作是思考的延伸，而排版与推送应当是无声的基础设施。
